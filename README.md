# 배송 송장 주소 자동 정제 프로그램

잘못 적힌 배송 송장 주소를 자동으로 고치고, 자동으로 고칠 수 없는 건은 사람이 확인하도록 따로 표시하는 Python 프로그램입니다.

## 1. 왜 만들었나

배달원으로 일할 때, 특정 업체의 송장 주소가 반복적으로 잘못 적혀 들어왔습니다.
업체와 IT팀에 수정을 요청했지만 바뀌지 않아, 매일 오후 배송 자료를 분류 전에 눈으로 확인해 팀장님께 전달하는 방식으로 오배송을 줄였습니다.

이 확인 작업은 매일 반복되지만, 물량이 많은 날에는 사람이 놓칠 수 있는 일이었습니다.
퇴사 후 AI 교육과정에서 개발을 공부하며, 그때 해결하지 못한 반복 작업을 직접 줄여보고 싶어 AI와 함께 이 프로그램을 만들었습니다.

## 2. 어떻게 동작하나

```
원본 엑셀 ──▶ ① 도로명 사전 학습 ──▶ ② 주소 자동 수정 ──▶ ③ 결과 표시
                (데이터에서 스스로)     (규칙 기반)           노란 칸: 자동 수정
                                                              빨간 칸: 확인필요(사람이 확인)
```

1. **도로명 사전 학습** — 같은 우편번호에서 자주 쓰인 정상 표기를 기준으로 삼습니다.
   새 파일이 들어오면 추가로 학습합니다. (`RoadDict` 클래스)
2. **자동 수정** — 아래 오류를 규칙으로 고칩니다.
   - 35자에서 잘린 도로명 복원 (`Yeongdong-daer` → `Yeongdong-daero`)
   - 도로명 오타 (`Taeheran-ro` → `Teheran-ro`, `Samsungro` → `Samseong-ro`)
     로마자 표기 차이(`Samsung`/`Samseong`)를 같은 값으로 묶은 뒤 유사도로 비교합니다. (`fold`, `strict_similar`)
   - 행정구역 표기 (`Kangnam-ku` → `Gangnam-gu`, `Sungnam city` → `Seongnam-si`)
   - 깨진 문자 `?`, 엑셀 오류값 `#NAME?`, Address1/Address2 중복, 우편번호 보완
3. **확인필요 표시** — 건물명만 있는 주소, 구와 우편번호가 맞지 않는 주소처럼
   규칙으로 판단할 수 없는 건은 고치지 않고 사유를 적어 사람에게 넘깁니다.

> 설계 원칙: **잘못 고치는 것이 안 고치는 것보다 위험하다.**
> 그래서 확실한 경우만 자동으로 고치고, 애매한 건은 사람이 최종 판단하도록 했습니다.

## 3. 결과 (실제 배송 자료, 2025.07 ~ 2026.01)

## 4. 직접 실행해 보기 (가상 데이터)

`sample/` 폴더에는 실제 자료의 오류 유형을 본떠 만든 **가상 데이터**가 있습니다.

```bash
pip install openpyxl
python sample/샘플생성.py                                  # sample/input/샘플_배송자료.xlsx 생성
python src/주소정제.py sample/input sample/output --relearn  # 정제 실행
```

결과: `sample/output/샘플_배송자료_정제.xlsx`, `sample/output/_주소정제_결과보고.xlsx`

## 5. 한계

- **건물명만 있는 주소**: 확인필요 7,055건 중 6,100건(약 86%)이 도로명 없이 건물명만 적힌 주소였습니다. 규칙으로는 어느 도로인지 알 수 없습니다.
- **규칙이 놓치는 표기**: 가상 데이터에서도 `268 Sonpa daero`(띄어쓰기 + 오타), 두 칸으로 끊긴 `GAN` + `GNAM-GU`, 짧게 잘린 `268 Son`은 자동으로 고치지 못했습니다. 이런 표기는 `수동사전.json`에 사람이 직접 추가해야 합니다.
- **정확도 미검증**: 자동 수정 31,108건이 실제로 맞게 고쳐졌는지는 아직 표본 검증 전입니다.
- **현장 미적용**: 퇴사 후 만들어 실제 현장에서 사용하지는 못했습니다.

## 6. 다음 단계

규칙으로 남은 부분을 **AI 에이전트**로 풀어보고 싶습니다.

- 건물명만 있는 주소 → 주소 검색 도구를 호출해 도로명 주소 후보를 찾는 에이전트
- 에이전트가 낸 수정안이 맞는지 **AI가 다시 검증하는 평가 단계** — 잘못 고치면 안 고친 것보다 더 위험하기 때문입니다. 이 검증으로 자동화의 결점을 보완하고, 사람이 직접 확인해야 하는 수동 검증을 줄이고 싶습니다.
- **토큰 수를 줄이는 구조** — 물동량 자료가 방대해 송장마다 AI를 쓰면 비용이 커집니다. 규칙으로 고칠 수 있는 건은 규칙으로 처리하고, 남은 건만 AI에 보내는 방식을 시도해 보고 싶습니다.

## 7. AI와 함께 만든 과정

먼저 검증해야할 자료를 전처리(회사명,이름,주소,연락처)등으로 맞추었습니다.
프롬프트를 작성할 때는 제가 업무의 전체적인 흐름을 먼저 작성했고,
거기서 나온 에러사항에 대해 개선사항을 작성하여 갈피를 잡았습니다.
실제 자료를 보여드리기에는 개인정보가 있기떄문에 SAMPLE을 만들어 검증확인을 할 수있게 만들었습니다.

## 8. 코드를 이해하기 위해 만든 설명본

`src/주소정제_설명.py` 는 원본 `주소정제.py` 의 코드에 줄마다 설명을 붙인 공부용 사본입니다.
코드는 원본과 동일하며, `# [설명]` 으로 시작하는 주석만 추가했습니다.

AI와 함께 만들다 보니 코드를 제가 완전히 이해하지 못한 채 넘어간 부분이 있었습니다.
그래서 위에서 아래로 읽는 대신, 프로그램이 실제로 동작하는 순서를 따라가며(탑다운) 이해하기로 했습니다.

1. `main` — 전체 흐름 3단계
2. `fix_address` — 주소 한 건을 고치는 중심 함수
3. `RoadDict` 의 `observe` / `build` / `lookup` — 도로명 사전이 배우고 찾는 방법
4. `complete_tail` / `road_fix` / `district_fix` — 오류 유형별 수정 규칙
5. `process_file` / `write_report` — 엑셀에 표시하고 보고서를 만드는 부분
